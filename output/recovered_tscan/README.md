## Reading a recovered file

* The header states the mangled symbol, package, receiver, address range,
  and the original `file:line` when the pcln tables allow it.
* Functions with a recovered signature become real Go declarations whose
  body is only a comment listing the original machine code, plus a
  `panic` when the function returns values.
* Free functions (no receiver) sit outside the reflection metadata, so no
  signature exists in the binary; those files keep the header, the
  address and the machine code, and omit the declaration rather than
  guessing one.
* `zz_types.go` per package holds the recovered type declarations so the
  recovered signatures refer to declared types.

## Known limits

* Parameter names are not stored in Go binaries; they are emitted as
  `arg0..argN`.
* Named results collapse to their types (`(n int, err error)` becomes
  `(int, error)`).
* Variadic-ness is recovered, but a variadic signature still renders as
  a slice when the flag is missing.
* Signatures use package *names* (`geo.Point`), not import paths, and the
  import block is not synthesised — a package compiles only after its
  imports are restored.
* Generic instantiations are de-duplicated by base name.
* Garble-obfuscated binaries keep the layout but lose readable names.
