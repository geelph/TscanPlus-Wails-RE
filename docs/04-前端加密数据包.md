# 04 · 前端加密数据包 `*.json.<hash>.enc`

Wails 前端的 `frontend/dist/assets/` 里除了 JS/CSS/字体，还有 5 个以 `.enc` 结尾的大文件 —— 它们是**前端自己加密后再打进包里的数据包**（POC 库、命令模板、导航树等）。

工具：[`tools/wails_enc_decrypt.py`](../tools/wails_enc_decrypt.py)

---

## 1. 信封格式

```js
const IVLEN = 12, TAGLEN = 16, KEYLEN = 32;
const KEY = "TscanPlus-Wiki-Encrypt-Key-32B!!";

iv  = buf.slice(0, IVLEN);
tag = buf.slice(-TAGLEN);
ct  = buf.slice(IVLEN, -TAGLEN);
pt  = await crypto.subtle.decrypt(
        { name: "AES-GCM", iv, tagLength: TAGLEN * 8 },
        await crypto.subtle.importKey("raw", enc(KEY), "AES-GCM", false, ["decrypt"]),
        concat(ct, tag));
json = JSON.parse(pako.ungzip(new Uint8Array(pt), { to: "string" }));
```

```
文件 = [IV(12)] [密文(n)] [TAG(16)]
      → AES-256-GCM（key 直接就是那 32 字节 ASCII）
      → gzip? → JSON
```

注意两个细节：

* key **不做派生**（不像 POC 库那样再过一层 SHA-256），32 字节明文直接当 AES key 用。JS 里能看到的字符串就是最终 key。
* gzip 是 `pako` 解的，属于"包装层"而不是加密层 —— 解完 GCM 后可能直接是 JSON，也可能还是 gzip，两个分支都要处理。

## 2. key 在哪

就在打包后的 JS 里，而且写得很直白：

```js
const IVLEN=12,TAGLEN=16,KEYLEN=32,KEY="TscanPlus-Wiki-Encrypt-Key-32B!!";
```

`wails_enc_decrypt.py --from-js index.*.js` 会按三条规则一起搜，然后把候选密钥**全部试一遍**（GCM 的 tag 校验让假阳性概率降到 2⁻¹²⁸，试错完全安全）：

1. 任意引号包起来的 **32 字节可打印字符串**；
2. `AES-GCM` / `importKey` / `subtle` 前后 ±600 字符范围内的 32 字节常量（命中率最高）；
3. 名字里带 `Key` 的赋值、`VITE_*_KEY` 之类的环境常量；长度不是 32 的按 JS 里的兜底逻辑做 SHA-256。

## 3. 用法

```bash
# 自动模式：目录里所有 *.enc + 从 JS 自动找 key
python tools/wails_enc_decrypt.py --dir out/frontend/dist/assets \
       --from-js out/frontend/dist/assets/index.3227ff1c.js

# 手动给 key（32 字节字符串 / hex 都行）
python tools/wails_enc_decrypt.py --dir out/frontend/dist/assets --key "TscanPlus-Wiki-Encrypt-Key-32B!!"

# 单文件 + 美化输出
python tools/wails_enc_decrypt.py webPayloads.json.791901ee.enc -o webPayloads.json \
       --key "TscanPlus-Wiki-Encrypt-Key-32B!!" --pretty
```

输出文件名规则：去掉末尾的 `.<8位hash>.enc`，还原成 `webPayloads.json`。**原始 `.enc` 默认保留**（不覆盖），这样密文和明文可以同时在目录里。

## 5. 一个容易踩的坑：`.enc` 不是"加密的 POC 库"

`webPayloads.json`（6.5 MB / 705 条）和 `pocs/`（9060 条）是**两套东西**：

| | `pocs/**`（9060） | `webPayloads.json`（705） |
|---|---|---|
| 位置 | Go 侧 `embed.FS`，后端读取 | 前端 `assets/`，浏览器读取 |
| 加密 | KnpClZd2 + AES-256-GCM + gzip | AES-256-GCM + gzip |
| 口令 | 汇编桩拼接（Frida 抓） | 明文写在 JS 里 |
| 内容 | 完整 nuclei 模板（`id/info/requests`） | 单条 payload 片段（请求特征 + 变体） |

两套都要解，缺一套就不完整。

## 6. 通用性

这个信封不是 TscanPlus 独有的，Wails / Electron 圈子里很常见（`<name>.<hash>.enc` + `pako.ungzip`）。只要满足：

* 3 段式 `IV|CT|TAG`；
* key 是 32 字节常量或能 SHA-256 派生；
* 明文是 gzip 或 JSON；

`wails_enc_decrypt.py` 可以直接拿来用 —— 把 `--from-js` 指向目标项目的 bundle 即可。
